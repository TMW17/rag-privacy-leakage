% ===================== §1 EXECUTIVE SUMMARY =====================
\section{Executive summary}

\begin{summarybox}
Sprint 4 operationalizes the Phase-3 evaluation as runnable, defense-grade artifacts and locks the
experimental spine. \textbf{It produces no new measurements}; it makes the existing findings
inspectable and demonstrable. This report is correspondingly short.
\end{summarybox}

\noindent\textbf{What was delivered.}
\begin{itemize}[leftmargin=1.4em,itemsep=1pt]
\item \textbf{Task 4.1 --- secure chatbot prototype}: a FastAPI chatbot wiring the RQ5-recommended
config \textbf{C01100} (L2 retrieval-time redaction + L3 conversation refusal) in front of the clean
synthetic index, plus a three-query smoke test and its honest reading.
\item \textbf{Task 4.2 --- results dashboard}: a read-only Streamlit dashboard over the committed
\texttt{results/phase3/} artifacts; six tabs; every value loaded (never hardcoded), missing files
surfaced as explicit errors.
\item \textbf{Unified web app} (\texttt{webapp/}): one FastAPI server merging the live chatbot and the
dashboard under a single visual shell, with the live-vs-static distinction made explicit.
\item \textbf{Task 4.4 --- phase lock}: a close-out commit and an annotated tag
(\texttt{phase3-defenses-v1}) sealing the experimental spine on the remote.
\end{itemize}

\noindent\textbf{The one finding worth stating.} The live chatbot reproduces, in front of a viewer,
the two headline qualitative results of Phase 3: the rule engine \emph{understates} leakage
(engine--human \kpa{}~$=0.164$, cited), and \textbf{cross-document linkability survives} the redaction
stack (family F2, judged $\approx$0.6--0.7, unreduced, cited). The prototype is a
\textbf{demonstration of C01100, not a certified system}, and it does \textbf{not} solve linkability.

\begin{keyfinding}
Phase 4 makes the Phase-3 results \emph{runnable and inspectable}. The cited headline is unchanged:
judged strict ASR \textbf{28.8\%~$\to$~17.3\%} (Sprint~3), F2 unreduced, judge--human
\kpa{}~$=0.827$ (validation; 0.843 is cross-vendor corroboration). Nothing in this sprint moves
those numbers.
\end{keyfinding}

% ===================== §2 TASK 4.1 — CHATBOT =====================
\section{Task 4.1 --- Secure chatbot prototype}

\subsection{Configuration and architecture}
The prototype runs the \textbf{C01100} operating point identified as the RQ5 knee in Sprint~3:
\textbf{L2} (retrieval-time PII redaction, Microsoft Presidio) $+$ \textbf{L3} (conversation-state
refusal), with the \texttt{audit\_log} and \texttt{confidence\_threshold} (a severity-$S$
circuit-breaker, default $S>10\Rightarrow$ suppress) controls on. The system under test is
\textbf{Claude Sonnet~4.6} (temperature~0); the index is the \emph{clean} (non-poisoned) synthetic
collection \texttt{phase2\_baseline\_seed42}. ACL is off (\texttt{l5\_acl=False}): the synthetic
corpus is uniformly severity~$\geq$3, so per-profile ACL has nothing to bite on (provenance-only;
Sprint~3~\S8).

\noindent\textbf{Implementation.} A FastAPI backend with an inline chat UI; a shared pipeline factory
used by both the server and the smoke test. L2 runs Presidio in a separate Python~3.11 subprocess
(\texttt{.venv-presidio}) behind a \textbf{fail-closed} boundary: on any worker error the chunk is not
passed through. A free pre-flight gate checks dependencies, the API key, that the clean index
responds, and that the Presidio worker redacts --- so the paid smoke calls cannot fail mid-run.

\subsection{Smoke test --- the only new empirical content}
Three queries were run through the live pipeline (profile \texttt{Internal}), at a measured cost of
\textbf{\$0.0157} (3 SUT calls; 1{,}498 input $+$ 747 output tokens). The responses and per-turn
audit verdicts are summarized in Table~\ref{tab:smoke}. \textbf{All three turns score
\texttt{no\_leak} ($S=0.0$) --- and that uniformity is the demonstration, not a safety result.}

\begin{caveatbox}
The uniform \texttt{no\_leak} / $S=0.0$ across all three turns is the \textbf{demonstration, not a
safety result}. Q1 shows L2's utility cost (an expected trade-off, not a defect); Q2 shows the
sev4-surname recall ceiling (0.51); Q3 shows linkability surviving. On Q2 and Q3 the rule engine says
\texttt{no\_leak} while a human reads a leak --- precisely the engine understatement (engine--human
\kpa{}~$=0.164$) established in Sprint~2 and the F2-unreduced result established in Sprint~3. The
prototype \textbf{demonstrates C01100; it is not certified and does not solve linkability.} The
17.3\% judged-ASR headline is unchanged.
\end{caveatbox}

% ===================== §3 TASK 4.2 — DASHBOARD =====================
\section{Task 4.2 --- Results dashboard}

A read-only Streamlit dashboard presents the Phase-3 story over six tabs (Overview / Ablation /
Security--Utility~(RQ5) / Risk matrix / Judge validation~(RQ3) / Exploratory probes). \textbf{It never
recomputes a metric, makes an API call, or fabricates data}: every figure and number is read from a
committed \texttt{results/phase3/} artifact through a pure data layer (\texttt{loaders.py}), and a
missing file renders as an explicit error rather than a made-up value. The headline metric cards and
the \kpa{} prose are interpolated from \texttt{final\_metrics.json}; the honesty conventions
(judged-primary / engine-lower-bound, F2 unreduced-not-worse, \kpa{}~0.827 validation vs 0.843
corroboration, probes single-run/direction-only) are carried verbatim into the UI.

\begin{keyfinding}
\textbf{A weak spot caught during the CHECK (recorded honestly).} An early version of the probes tab
embedded a few metric \emph{literals} instead of loading them. The verification flagged it and the
values were rewired to load from \texttt{l2\_llm/l2\_llm\_results.json} before commit. The
``never hardcode a number'' rule is only meaningful if it is actually enforced --- it was.
\end{keyfinding}

% ===================== §4 UNIFIED WEB APP =====================
\section{Unified web app (\texttt{webapp/})}

The two deliverables --- a FastAPI chatbot and a Streamlit dashboard --- are two servers. They were
merged under \textbf{one FastAPI server} by porting the dashboard's \emph{views} into FastAPI
(architecture option ``b''), chosen because the dashboard's data layer (\texttt{loaders.py}) is
framework-agnostic (no Streamlit imports), so it ports cheaply, whereas the chatbot's stateful,
subprocess-backed pipeline does not survive a port into Streamlit's rerun model.

\noindent\textbf{Behaviour unchanged, by construction.} The chatbot's request handlers are
\textbf{re-registered as the exact same function objects} from the committed server, not retyped, so
\texttt{/chatbot/chat} drives the identical C01100 pipeline (same lazy scenario init, same audit
record, same \texttt{.venv-presidio} subprocess). This was \emph{verified by running it}: one live
turn through the unified endpoint returned the \textbf{same retrieved \texttt{doc\_ids}}
(\texttt{hr\_file\_052/039/072/090/045}), the \textbf{same \texttt{no\_leak} / $S=0.0$} verdict, and
the full layer stack fired, matching the committed standalone smoke (Q2). Cost of the verification:
$\approx$\$0.01. The dashboard's data layer is imported \emph{unchanged}.

\noindent\textbf{Honesty preserved and promoted.} One visual shell, with explicit \textbf{LIVE}
(real Claude calls) vs \textbf{STATIC} (committed artifact reads) ribbons so a viewer always knows
which is which. The chatbot's engine-blindness caption is \emph{promoted} from a footnote to a
prominent always-on band; the \texttt{no\_leak} verdict renders \textbf{amber, never green}, always
paired with ``engine view~$\cdot$~\kpa{}~$=0.164$ lower bound~$\cdot$~not a safety guarantee.'' There
is no \emph{Protected\,/\,Safe\,/\,Secure} framing anywhere; the committed honest reading is embedded
on the chatbot page, with a note that live responses vary run-to-run (temperature-0 nondeterminism)
so the frozen smoke evidence --- not any single live generation --- is the reproducible demonstration.

\begin{keyfinding}
\textbf{A second weak spot caught during the CHECK.} The verification's ``no new hardcoded numbers''
test first used a regex that required a call \texttt{L.name(}; but the dashboard passes loaders as
\emph{references} (\texttt{guard(L.six\_cell)}), so the pattern matched nothing and the check passed
\emph{vacuously} (empty~$\subseteq$~empty). It was fixed to match references regardless of call
syntax; it now compares \textbf{13 real loader symbols} and confirms every loader the dashboard uses
is still used by the unified app. A passing check that does not check is worse than no check --- this
one was caught.
\end{keyfinding}

% ===================== §5 TASK 4.4 — LOCK =====================
\section{Task 4.4 --- Phase lock}

The experimental spine was sealed with a close-out commit and an \textbf{annotated} git tag,
\texttt{phase3-defenses-v1}, pushed to the remote (the tag dereferences to the close-out commit). The
tag message records the honest headline so the seal carries its own framing: judged strict ASR
\textbf{28.8\%~$\to$~17.3\%} ($\approx$40\% relative, F1-carried); \textbf{F2 linkability unreduced};
\textbf{judge--human \kpa{}~$=0.827$} as the validation (0.843 is cross-vendor corroboration); the
RQ5 knee \textbf{C01100}; the Presidio recall ceiling; the two exploratory probes walled off as
single-run, direction-only; and ``synthetic demonstration, not certified.'' Cumulative measurement
spend at the lock was \textbf{$\approx$\$19.1 of a $\approx$\$32 envelope}.

\begin{keyfinding}
The tag seals the \textbf{experimental spine} (defenses built and ablated, headline established and
hedged, artifacts runnable) --- it does \emph{not} mark project completion. \textbf{Phase 5 (the
60--80\,pp thesis) and Phase 6 (defense, best-practices guide, publication) remain}, and are the bulk
of the work left.
\end{keyfinding}

% ===================== §7 CONCLUSION =====================
\section{Conclusion and transition to Phase 5}

Sprint 4 turned the Phase-3 evaluation into runnable artifacts and sealed the experimental spine. The
secure chatbot demonstrates, live, the engine understatement and the surviving linkability that the
measurements established; the dashboard makes every committed number inspectable without recomputation;
the unified web app presents both under one honest shell; and the annotated tag fixes the result on the
remote with its framing intact. \textbf{No number changed}: the cited headline remains 28.8\%~$\to$~17.3\%
judged strict ASR, F2 unreduced, judge--human \kpa{}~$=0.827$. Two verification weak spots --- a
hardcoded-literal slip in the dashboard and a vacuous loader-diff in the unified app --- were caught and
fixed, consistent with the project's discipline of preferring the defensible truth to the convenient one.

\noindent The work now moves to \textbf{Phase 5}: the 60--80\,page thesis (a separate document from the
four Sprint reports), the best-practices guide, and the regulatory recommendations --- built on the
frozen artifacts this sprint locked, not re-derived from them.
